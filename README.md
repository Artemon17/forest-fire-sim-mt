## О проекте

Лесной массив — клеточная карта с растительностью, водоёмами и противопожарными рвами.
Датчики замечают огонь и шлют сообщения в центр, центр отправляет к очагам ограниченное число
пожарных групп, группы идут к очагу и тушат его. Огонь тем временем распространяется.

Это многопоточная версия последовательной имитации из ИЗ №1. Сущности, у которых есть собственное
поведение во времени (датчики, пожарные группы, распространение огня), представлены потоками.

Один такт состоит из фаз:

```
наблюдение → сообщения → решения → движение → тушение → распространение огня → рендер
```

Порядок фаз строго фиксирован, состояние публикуется только после завершения всех фаз.

## Сборка

```bash
make fire       # основная программа (семафоры + барьеры + мьютексы)
make fire-cv    # альтернативная программа (condvar вместо семафоров)
make all        # обе
make clean      # очистка
```

Сборка идёт с `-Wall -Wextra -Wpedantic` и проходит без предупреждений.

## Запуск

```bash
# одна станция в точке (11, 13)
./build/fire --map data/map_big_01.map --station 11 13 --seed 42

# перебор всех кандидатов на станцию из карты, без отрисовки
./build/fire --map data/map_big_01.map --station-scan --seed 42 --quiet

# альтернативная версия
./build/fire-cv --map data/map_big_01.map --station 11 13 --seed 42
```

### Аргументы командной строки

| Опция | Назначение |
|---|---|
| `--map FILE` | файл карты |
| `--conditions FILE` | файл конфига (по умолчанию `data/conditions.conf`) |
| `--station R C` | поставить станцию в клетку (R, C) |
| `--station-scan` | перебрать всех кандидатов из карты |
| `--seed N` | фиксированный seed генератора случайных чисел |
| `--delay MS` | задержка между тактами, мс |
| `--quiet` | не рисовать кадры |
| `--no-ansi` | без ANSI-последовательностей |

### Управление

- `q` — выход
- `Ctrl+C` — прерывание (корректное завершение через `sigaction`)

### Коды возврата

| Код | Значение |
|---|---|
| 0 | нормальное завершение |
| 2 | ошибка аргументов |
| 3 | ошибка конфига |
| 4 | ошибка карты |
| 5 | станция вне карты |
| 130 | прервано пользователем |

## Потоки и синхронизация (кратко)

| Фаза | Что делает | Потоки | Синхронизация |
|---|---|---|---|
| 1. Датчики | сканируют округу | N | `pthread_barrier_t` |
| 2. Сообщения | `in_flight` → `inbox` | main | `in_flight.lock` |
| 3. Центр | `inbox` → задачи | main | — |
| 4–5. Команды | BFS и тушение | K | барьер + `teams_lock` |
| 6. Огонь | пересчёт сетки | W | `sem_t` (в `fire-cv` — condvar) |
| 7. Рендер | вывод кадра | main | — |

Типичная конфигурация: 1 main + 6 сенсоров + 5 команд + 8 fire-воркеров = 20 потоков.

Основные правила:

- порядок захвата мьютексов: `teams_lock` → `log.lock`, никогда наоборот;
- fire-воркеры пишут в буфер `_Atomic FireState next_state[]` без мьютекса;
- генератор случайных чисел — `rand_r` с отдельным seed на каждый поток;
- завершение: `atomic_store(&stop, 1)` → пробуждение всех → `pthread_join` → освобождение ресурсов.

Подробности, анализ гонок и обоснования — в [`REPORT.txt`](REPORT.txt).

## Проверка

```bash
# гонки данных
valgrind --tool=helgrind ./build/fire    --map data/map_big_01.map --station 11 13 --seed 42 --quiet
valgrind --tool=helgrind ./build/fire-cv --map data/map_big_01.map --station 11 13 --seed 42 --quiet

# утечки памяти
valgrind --leak-check=full ./build/fire --map data/map_big_01.map --station 11 13 --seed 42 --quiet

# набор тестов
tests/run_all.sh
```

Результаты: helgrind — 0 errors; memcheck — 0 leaks (139 allocs / 139 frees);
стресс-тест на 20 seed — 0 провалов на обеих версиях.
Логи: `docs/helgrind.log`, `docs/memcheck.log`.

## Известные ограничения

- Команды сериализуются через `teams_lock`, поэтому на малых картах MT-версия не быстрее последовательной.
- Результат при одном seed может отличаться между прогонами (11 vs 15 тактов) — это недетерминизм планировщика, а не гонка данных.
- Из-за per-thread RNG нет побитового совпадения с последовательной версией.
